# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Astro 6 static site for Sina Hotpot (Chinese hotpot restaurant, Prato + Firenze), built with Tailwind CSS v4 and deployed to Cloudflare Workers via Wrangler. Five locales, no CMS: all content lives in typed TypeScript modules under `src/data`.

## Commands

```bash
npm run dev             # astro dev
npm run check           # astro check (Astro + TS diagnostics)
npm run build           # astro check && astro build -- must report zero diagnostics
npm run preview         # build, then serve the Worker locally with wrangler dev
npm run deploy          # build && wrangler deploy
npm run generate-types  # wrangler types -> worker-configuration.d.ts
```

There is no test suite and no linter. `npm run build` (which runs `astro check`) is the only gate; run it after non-trivial changes.

Node >= 22.12. Env vars live in `.env` (git-ignored) and are declared in the `env.schema` block of [astro.config.mjs](astro.config.mjs) — a variable not declared there is not importable from `astro:env/client`.

## Architecture

### Routing and i18n (the part that trips people up)

Astro i18n config: locales `it | zh | en | es | fr`, default `it`, `prefixDefaultLocale: false`. That means **every page exists twice in the source tree**:

- Default (Italian) routes are explicit files: [src/pages/index.astro](src/pages/index.astro), [src/pages/gallery.astro](src/pages/gallery.astro), etc. Each is a 3-line wrapper that renders the page component with `locale="it"`.
- All non-Italian routes are generated by the catch-all [src/pages/[locale]/[...slug].astro](src/pages/[locale]/[...slug].astro), which maps a `PageId` to a page component and gets its paths from `getLocalizedStaticPaths()`.
- Culture topics have the same split: [src/pages/hotpot-culture/[topic].astro](src/pages/hotpot-culture/[topic].astro) for Italian, the catch-all for the rest.

[src/data/routing.ts](src/data/routing.ts) is the single source of truth for locales, `pageSlugs`, `cultureTopicSlugs`, nav order, and the `getPath()` / `getCultureTopicPath()` URL builders. **Never hardcode a URL** — always go through these helpers, since they encode the default-locale prefix rule.

**Adding a page** requires: a slug in `pageSlugs`, membership in `localizedStaticPages` (and `primaryNavPages` if it belongs in the nav), a page component under `src/components/pages/`, an entry in the `pageComponents` map in the catch-all route, an Italian wrapper file in `src/pages/`, `nav`/copy entries in all five `src/data/copy/*.ts` files, and SEO meta in [src/data/seo.ts](src/data/seo.ts).

### Data layer

`src/data/*.ts` files at the top level are **public barrels**; the folders next to them hold the implementation. Components import from the barrel ([src/data/site.ts](src/data/site.ts), `copy.ts`, `cultureTopics.ts`, `homeSections.ts`), not from the folder internals.

- [src/data/site.ts](src/data/site.ts) — the main import for pages/layouts: re-exports all of `routing.ts` plus restaurant metadata.
- [src/data/restaurant.ts](src/data/restaurant.ts) — brand, legal footer lines, and the two locations, typed with `as const satisfies`.
- [src/data/copy/](src/data/copy/) — UI strings split one file per locale, shape enforced by `copy/types.ts`. Widening that type forces all five locale files to be updated (intentional; the build fails until they are).
- [src/data/cultureTopics/](src/data/cultureTopics/) — one file per topic, each holding all five locales for that topic (the opposite split from `copy/`). Same for `homeSections/`, which splits by locale.
- [src/data/gallery.ts](src/data/gallery.ts) and `restaurant.ts` build image lists with eager `import.meta.glob`, sorted numerically by filename via [src/data/imageAssets.ts](src/data/imageAssets.ts). **Gallery order is filename order** — [scripts/gallery_order.py](scripts/gallery_order.py) is an interactive helper that shuffles or swaps those numbered filenames. Dropping a file into the right folder is enough; no registration step.

### Opening hours are duplicated by design

Each location in `restaurant.ts` carries `hours` (display string), `schemaOpeningHours` (schema.org), and `reservationTimeRanges` (drives the reservation `<select>` through `getReservationTimeSlots()` in [src/utils/reservation.ts](src/utils/reservation.ts), at 30-minute steps, handling past-midnight ranges). **Change all three together** or the site, structured data, and booking form will disagree.

### Layout and SEO

[src/layouts/SiteLayout.astro](src/layouts/SiteLayout.astro) is the only document shell. It takes `locale` + `page` and derives title/description from `getPageSeoMeta()`, plus canonical URL, hreflang links (including `x-default`), Open Graph/Twitter tags, and the `@graph` JSON-LD (WebSite + Organization + one Restaurant per location) from [src/data/seo.ts](src/data/seo.ts). Pages pass `title`/`description`/`alternatePaths`/`socialImage` overrides only when they are not plain static pages — see `CultureTopicPage.astro` (per-topic alternates) and `SuccessPage.astro` (`noindex`).

Hiding a page from search means both `noindex` on the layout *and* an entry in `hiddenSitemapPaths` / the serialize filter in [astro.config.mjs](astro.config.mjs).

### Component and styling conventions

- `src/components/pages/*` = one component per route, renders `SiteLayout` plus sections. `src/components/home/*` and `locations/*` = page-specific sections. `src/components/ui/*` = small primitives (`CtaLink`, `SectionHeader`).
- Tailwind v4 through `@tailwindcss/vite`; design tokens are declared in the `@theme` block of [src/styles/global.css](src/styles/global.css) (`bg-ink`, `text-gold`, `border-warm-line`, …). There is no `tailwind.config`.
- **Class strings are not inlined in markup.** Every component declares local `sectionClasses` / `layoutClasses` / `cardClasses` / `textClasses` / `mediaClasses` objects in its frontmatter, usually composed from the shared maps in [src/utils/ui.ts](src/utils/ui.ts). Follow this pattern in new components.
- Images use `astro:assets` `<Image>` with a width/widths/sizes preset from `imageSizes` in `src/utils/ui.ts`. Images are imported from `src/assets/images` (optimized at compile time via `imageService: "compile"`); `public/` holds only favicons and similar raw files.

### Client scripts

Minimal progressive enhancement in [src/scripts/](src/scripts/), imported from inline `<script>` blocks in the component that needs them (`SiteLayout` loads `headerMenus` + `googleAdsConversions`; `HomePage` loads `homeReveal`). Scripts hook onto stable `data-*` attributes (`data-reservation-form`, `data-reservation-time`, …) through the `queryOne`/`queryAll` helpers in `scripts/dom.ts` — never onto Tailwind classes. Localized strings a script needs are passed down as `data-*` attributes on the element, since scripts have no access to `copy`.

### Reservation flow

[src/components/ReservationForm.astro](src/components/ReservationForm.astro) renders the form; [src/scripts/reservationForm.ts](src/scripts/reservationForm.ts) POSTs directly to Web3Forms from the browser, then redirects to the localized success page and fires a Google Ads conversion. Time options are filtered per selected location, and the date minimum shifts to tomorrow when the chosen time has already passed today. `PUBLIC_WEB3FORMS_ACCESS_KEY` and `PUBLIC_WEB3FORMS_CAPTCHA_ENABLED` (hCaptcha is fully conditional — component, script load, and token check) control it. A planned server-side Resend replacement is specced in [docs/resend-migration.md](docs/resend-migration.md).

### Analytics and consent

Google Ads gtag is bootstrapped in [src/components/GoogleAdsTag.astro](src/components/GoogleAdsTag.astro) with consent **denied by default**; [src/scripts/cookieConsent.ts](src/scripts/cookieConsent.ts) grants it after the banner is accepted (choice stored in `localStorage`). IDs and conversion labels live in [src/scripts/googleAdsConsent.ts](src/scripts/googleAdsConsent.ts).

### Deployment

`output: "static"` with the Cloudflare adapter and compile-time image optimization — adding a server endpoint (e.g. the Resend migration) requires switching the output mode, otherwise image requests cannot be served. Worker config is in [wrangler.jsonc](wrangler.jsonc); `dist/` is served as static assets.
